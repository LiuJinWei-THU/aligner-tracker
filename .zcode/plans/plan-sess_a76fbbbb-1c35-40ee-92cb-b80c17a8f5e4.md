# 牙套佩戴计时 PWA — 实现计划

## 目标
做一个纯静态、无后端的单页应用（PWA），托管到 GitHub Pages，安卓手机浏览器打开后可"添加到主屏幕"，像 app 一样离线使用。点击"摘下/戴上"记录事件，自动统计每日实际佩戴时长，目标 22 小时/天，并可视化。

## 技术选型
- **纯 Vanilla HTML/CSS/JS，零外部依赖**（不用 Chart.js 等 CDN，图表手写 SVG）→ 保证 Service Worker 缓存后完全离线可用
- **数据存 localStorage**（绑定 GitHub Pages 域名，稳定持久），提供 **JSON 导出/导入** 作为备份和换机迁移手段
- 界面全中文，移动端优先（大按钮、单手操作）

## 文件结构
```
牙套计时项目/

```

## 数据模型
```js
{
  version: 1,
  settings: { dailyGoalHours: 22 },
  events: [ { id, type: 'on'|'off', ts: 毫秒时间戳 } ]  // 按时间排序
}
```

## 核心逻辑（stats.js，重点保证正确性）
- 当前状态由最后一个事件推导；无任何事件时默认"正在佩戴"
- 未佩戴区间 = 相邻 off→on 事件对；**每日佩戴时长 = 24h − 当日未佩戴时长**
- **跨天切分**：未佩戴区间若跨越午夜，按自然日（本地时区 00:00）切分归属到每一天 —— 夜里戴着睡觉不会算错
- 正在摘着时（最后一个事件是 off），统计到"当前时刻"为止
- 连续两个相同类型事件（如忘了点导致两次 off）取第一个生效，记录页显示警告标记
- 第一天基线：假设从当天 00:00 起在佩戴（有误差可通过补录修正）

## 界面（3 个 Tab）

**① 今天（主页）**
- 超大切换按钮：戴着时显示绿色"摘下牙套"，摘着时显示橙色"戴上牙套"
- 今日已佩戴 X 小时 Y 分 + 环形进度（22h 目标）
- 实用提示："今天还能摘 Y 小时 Z 分"
- 本次摘下/戴上已过多久、今日摘戴次数

**② 统计**
- 近 7 天 / 近 30 天切换
- **每日佩戴柱状图**（SVG，22h 目标虚线，达标绿色/未达标橙色，y 轴 0–24h）
- **每日时间线**：每天一条 24h 横条，标出每段没戴的时间区间（一眼看出吃饭时段）
- **汇总卡片**：周/月平均佩戴时长、达标天数、连续达标天数（streak）、达标率

**③ 记录**
- 按天分组的事件列表，每条可**编辑**（改时间、改类型）、**删除**（带确认）
- **补录**按钮：手动添加过去某时刻的摘/戴事件（解决忘按问题）
- **导出 JSON / 导入 JSON**（备份、换手机迁移）
- 目标小时数设置（默认 22）

## PWA
- manifest.json：standalone 显示、中文名"牙套计时"、主题色、192/512 图标（Python 生成简单牙齿图形 PNG）
- sw.js：cache-first 策略缓存全部静态文件，版本号更新时自动清理旧缓存

## 测试与验证
1. **stats.js 单元测试**（node 脚本）：跨午夜切分、连续同类事件、首日基线、正开放区间等边界用例
2. **本地起静态服务器**（python http.server），用浏览器自动化实际点击摘/戴按钮、补录、编辑，截图验证三个页面和图表渲染
3. Service Worker 在本地 http 环境验证离线缓存生效
